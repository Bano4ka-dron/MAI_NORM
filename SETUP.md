# Запуск проекта

Веб-приложение виртуальной примерки одежды: Flask-бэкенд + статические HTML/CSS/JS страницы.
Примерка выполняется через Hugging Face Space `Kwai-Kolors/Kolors-Virtual-Try-On`.

## Требования

- Python 3.10 или выше (gradio-client требует >= 3.10)
- Интернет (для обращения к Hugging Face Space)

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS

pip install -r server/requirements.txt
```

## Настройка секретов

```bash
copy .env.example .env          # Windows
# cp .env.example .env          # Linux / macOS
```

Откройте `.env` и укажите свой токен Hugging Face:

```
HF_TOKEN=hf_ваш_токен
```

Токен создаётся здесь: https://huggingface.co/settings/tokens (достаточно роли Read).
Без токена приложение тоже работает, но Space может ограничивать анонимные запросы.

Файл `.env` добавлен в `.gitignore` и не должен попадать в репозиторий.

## Запуск сервера

Команду нужно выполнять **из корня проекта** — часть кода обращается к базе
`users_database.db` по относительному пути.

```bash
cd server
python server.py
```

Сервер поднимется на `http://localhost:5000` (debug-режим включён).
При старте `users_bd.py` автоматически создаёт таблицы, если их нет.

## Адрес сервера (config.js)

В проекте **нет жёстко прописанных IP и портов**. Адрес Flask-сервера вычисляется
автоматически в файле `config.js` из адреса открытой страницы:

| Как открыта страница                  | Куда идут запросы к API            |
| ------------------------------------- | ---------------------------------- |
| `http://127.0.0.1:5500/index/...`     | `http://127.0.0.1:5000/api/...`    |
| `http://192.168.1.42:5500/index/...`  | `http://192.168.1.42:5000/api/...` |
| `file:///.../index/index.html`        | `http://localhost:5000/api/...`    |

Поэтому проект одинаково работает и на своём компьютере, и на чужом, и по сети —
менять ничего не нужно. Если порт Flask меняется, поправьте `SERVER_PORT`
в `config.js` и порт в `server/server.py`.

## Страницы интерфейса

Фронтенд — это отдельные статические страницы. Их открывают напрямую в браузере
(файлом или через Live Server), пока запущен бэкенд на порту 5000:

> **Важно:** сначала запустите `server.py`, иначе страницы не смогут загрузить
> товары из базы и покажут ошибку соединения.

| ----------- | ------------------------------ |

| `Login/`    | Вход                           |
| `Register/` | Регистрация                    |
| `prof/`     | Профиль (мерки и фото)         |
| `Fitting/`  | Виртуальная примерка           |
| `Saved/`    | Сохранённые результаты         |

## Виртуальная примерка (движки)

Примерка выполняется через Hugging Face Spaces. Движки лежат в
`server/backends.py`, порядок попыток — в `TRYON` в начале `server/server.py`.

| Движок | Space | Что принимает за один вызов |
| ------ | ----- | --------------------------- |
| `idm_vton` | `yisol/IDM-VTON` | фото человека + **одно** фото вещи |
| `qwen_edit` | `Qwen/Qwen-Image-Edit` | одно фото + текст с описанием вещи |
| `kolors` | `Kwai-Kolors/Kolors-Virtual-Try-On` | фото человека + одно фото вещи (API закрыт) |

### Несколько вещей надеваются по очереди

Ни один из этих Spaces не принимает несколько фото одежды сразу:
у IDM-VTON один вход `garm_img`, у Qwen-Image-Edit вообще один вход
под картинку (`image[6]`), у Kolors — один `garment_img`.

Поэтому если выбрано несколько вещей, сервер надевает их
**последовательно одной цепочкой**:

```
шаг 1: исходное фото человека + вещь №1  ->  результат 1
шаг 2: результат 1            + вещь №2  ->  результат 2
шаг 3: результат 2            + вещь №3  ->  итог
```

Результат каждого шага сохраняется как `step1_*.png`, `step2_*.png`, а
итоговый — как `gen_*.png`. В ответе API приходит `garments_applied`
(сколько вещей надето) и `backend` (какой движок сработал).

Если движок падает на любом шаге, сервер начинает цепочку заново
следующим движком.

### Прогресс

Так как вещей может быть несколько, страница примерки опрашивает
`GET /api/generate/progress?user_id=N` и показывает «Шаг 2 из 3: …».
Если пользователь закроет страницу, примерка на сервере продолжится.

**Учитывайте время:** примерка из 3 вещей — это 3 генерации подряд,
то есть в 3 раза дольше, чем одна.

### Важно про квоту

Все Spaces с примеркой работают на ZeroGPU. Бесплатная квота — примерно
**110 секунд GPU в сутки** на аккаунт Hugging Face, а одна примерка просит
около 240 секунд. Если квота исчерпана, Space отвечает ошибкой:

```
You have exceeded your free ZeroGPU quota
```

Квота восстанавливается примерно через сутки. Варианты: подождать, оформить
Hugging Face PRO (25 минут GPU в день) или поднять свой Space с оплатой по факту.

### Проверка примерки

```bash
cd server
python test_tryon.py        # 2 вещи по очереди
python test_tryon.py 1      # только 1 вещь
```

Скрипт возьмёт человека и товары прямо из базы, прогонит цепочку шагов
и покажет, какой движок сработал, за сколько секунд и какие файлы созданы.

## Демо-данные

В репозиторий включены:

- `users_database.db` — каталог из 4 товаров и демо-пользователь;
- `uploads/user_1/` — примеры результатов генерации и исходное фото.

Новые фото, загруженные через сайт, в репозиторий не попадают (см. `.gitignore`).

## Структура

```
.
├── admin/ Catalog/ Data/ Fitting/ Login/ Register/
├── Saved/ Upload/ Wishlist/ index/ prof/    # страницы интерфейса (html/css/js)
├── images/                                  # картинки интерфейса и товары
├── server/
│   ├── server.py            # Flask API + прогресс примерки
│   ├── backends.py          # движки примерки (Hugging Face Spaces)
│   ├── users_bd.py          # работа с SQLite + создание таблиц
│   ├── test_tryon.py        # живая проверка примерки
│   └── requirements.txt
├── uploads/                 # загрузки пользователей (по папкам user_<id>)
├── users_database.db        # база SQLite
├── config.js                # автоопределение адреса Flask-сервера
└── .env.example
```

## Основные эндпоинты API

| Метод | Путь                        | Назначение                        |
| ----- | --------------------------- | --------------------------------- |
| POST  | `/api/save`                 | Регистрация                       |
| POST  | `/api/login`                | Вход                              |
| GET   | `/api/products`             | Список товаров                    |
| GET   | `/api/admin/products`       | Все товары (админ)                |
| POST  | `/api/admin/product`        | Добавить товар                    |
| POST  | `/api/admin/product/delete` | Удалить товар                     |
| GET   | `/api/wishlist`             | Избранное пользователя            |
| POST  | `/api/wishlist/toggle`      | Добавить/убрать из избранного     |
| GET   | `/api/user/data`            | Мерки пользователя                |
| POST  | `/api/user/data`            | Сохранить мерки                   |
| POST  | `/api/upload/photos`        | Загрузить фото пользователя       |
| GET   | `/api/user/photos`          | Список фото пользователя          |
| POST  | `/api/generate/tryon`       | Виртуальная примерка (все вещи)   |
| GET   | `/api/generate/progress`    | Прогресс: какой шаг выполняется   |
| GET   | `/api/generations`          | Сохранённые примерки              |
| POST  | `/api/generations/delete`   | Удалить примерку                  |
